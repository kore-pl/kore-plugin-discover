# kore-plugin-discover — руководство по использованию

Плагин обнаружения локальных служб для kore (id `discover`): автоматически определяет, какие служебные службы установлены на узле, где они находятся и работают ли они. Только для чтения: не устанавливает пакеты, не меняет конфигурацию, не запускает и не останавливает службы.

## Установка и совместимость

Устанавливайте опубликованный tar.gz через установщик плагинов kore; репозиторий также можно собрать отдельно (`make build` / `make dist`). Протокол `kore.plugin.v1`, `requires_kore: >=0.1.0 <0.2.0`, `lifecycle=lazy`, уровень глубины `production`. Linux — единственная реальная реализация; на других платформах все методы возвращают `E_UNSUPPORTED`.

## Методы

| Метод | Вход | Ключевой результат |
| --- | --- | --- |
| `kore.ping` | `{}` | `{status,uptime_s,goroutines,rss_kb}` |
| `kore.reload` | `{}` | Пустая операция без состояния, `config_digest` пуст |
| `kore.shutdown` | `{}` | `{ok:true}`, затем корректный выход |
| `discover.services` | `{}` или `{"refresh":true}` | Массив из 22 типов служб: пути, версии клиента/сервера, состояние и подсказки |
| `discover.ports` | `{}` или `{"refresh":true}` | Локальные LISTEN-порты, адреса, семейство и имена процессов |
| `discover.summary` | `{}` или `{"refresh":true}` | `{ready,web_server,db,conclusion,suggestions[]}` краткий вывод и рекомендации плагинов |
| `discover.config.get` | `{}` | Объявления, состояние внедрения и подсказки по учётным данным (значения nunca не возвращаются) |

Результаты кэшируются 30 секунд; `refresh=true` принудительно выполняет новое обнаружение.

## Как читать результаты

- `found=false` всегда содержит `install_hint` (команды для Debian/Ubuntu и RHEL); `source ∈ which|known_path|systemd|process`.
- `server_version` заполняется только после реального подключения к серверу; `version_source ∈ server|client|unknown`. `client_version` — версия самого бинарника, её нельзя выдавать за версию сервера.
- Если есть только клиент, `version_hint` объясняет, какая переменная учётных данных отсутствует, где её указать или почему сервер недоступен.
- `running` учитывает прослушиваемые порты, `/proc/<pid>/comm` и признаки запуска; процессы контейнеров и перенаправленные порты не считаются службами хоста.

## Граница учётных данных

Проверки версий серверов MySQL / PostgreSQL / Redis используют `MYSQL_PWD` / `PGPASSWORD` / `REDISCLI_AUTH`. Учётные данные читаются только из переменных окружения процесса, никогда не попадают в argv, на диск или в логи; `config.get` возвращает только объявления и состояние. Плагин не предоставляет `config.set` и не принимает пароли в открытом виде.

## Сборка и проверка

```bash
make check   # gofmt + go vet + go test -timeout 200s (включая проверку race)
make build   # статический одиночный бинарник bin/discover
make dist    # детерминированный tar.gz и .sha256
```
